## 1. `_` 忽略变量

**是什么**：循环/解包里那个"我拿到了但用不上"的变量，按 Python 社区约定写成下划线 `_`。

```python
for _ in range(4):          # 只需要"循环 4 次"，不需要循环变量的值
    t.forward(100)

a, _, c = (1, 2, 3)         # 解包时丢掉中间那个
```

**为什么**：`_` 本质就是个普通变量名，解释器对它没有任何特殊处理——它只是个**约定**，用来告诉读代码的人「这个值是故意不用的」。

**C/C++ 对照**：C/C++ 循环里你还得 `for (int i = 0; ...)` 硬造一个 `i`；Python 直接 `_` 表达"我不要"。

**坑**：交互式解释器（REPL）里 `_` 会被自动赋值为"上一次的结果"，别在脚本里依赖这个副作用，两者是两码事。

## 2. 全大写 = 约定常量

**是什么**：模块级全大写变量，表示"逻辑上的常量"，例如 `CELL = 20`、`WIDTH, HEIGHT = 620, 620`。

```python
CELL = 20        # 格子大小，约定上不该改
STAR_PROBABILITY = 0.35
```

**为什么**：Python **没有真正的 `const`**。全大写只是**约定**，改了值解释器不会报错（不像 C++ 的 `const` 在编译期就禁止修改）。

**C/C++ 对照**：

| | C++ | Python |
|---|---|---|
| 真常量 | `const int CELL = 20;` 改了编译报错 | 无；全大写只是约定 |
| 宏 | `#define CELL 20` | 不用，直接全大写变量 |

**坑**：别因为看着像常量就以为"改了会报错"——它不会。靠自觉和团队约定。

## 3. `enumerate`：同时拿下标和值

**是什么**：遍历序列时，同时拿到「下标」和「元素值」，不用自己维护计数器。

```python
for i, n in enumerate([3, 4, 5]):
    # i = 0, 1, 2   ← 下标
    # n = 3, 4, 5   ← 值
```

**为什么**：替代 C++ 里 `for (int i = 0; i < v.size(); i++) v[i]` 的套路，更简洁、更不易越界。

**进阶**：`enumerate(序列, start=1)` 可指定起始下标（比如从 1 开始编号）。

## 4. 动态属性：运行时给对象挂新成员

**是什么**：Python 允许**随时给对象加新属性**，不必在类里预先声明。

```python
head = turtle.Turtle()
head.direction = "stop"     # Turtle 类里本没有 direction，运行时照样能加
```

**为什么**：Python 对象内部有个 `__dict__` 字典存属性，运行时增删都合法。对比 C++：类成员必须在类定义里声明，编译期定死，不能"用到才加"。

**重要坑（你 08 课踩过的）**：运行时合法 ⇒ 游戏能正常跑；但**静态类型检查器（Pylance）不认**这种写法，会认为 `Turtle` 没有 `direction` 成员，于是每一处 `head.direction` 都画红线（你之前看到的"08 课全是报错"正是这个）。已通过根目录 `pyrightconfig.json` 把类型检查关掉解决，**不影响运行**。

**替代**：若想让类型检查彻底安静，可改成独立全局变量 `direction = "stop"`，但那样就丢掉"动态加属性"这个教学点。

## 5. 列表特性：负数下标 + 混装任意类型

**是什么**：

```python
COLORS = ["red", "green", "blue"]
COLORS[-1]        # "blue"，负数下标从末尾数，-1 是最后一个
COLORS[-2]        # "green"

mixed = [1, "hello", 3.14, True]   # 一个列表里混装不同类型，完全合法
```

**为什么**：
- 负数下标是 Python 的便利语法糖，读起来比 `len-1` 直观。
- 列表"混装任意类型"是因为 **list 存的是对象引用，而 Python 变量本身就没有类型**——所以装啥都行。对比 C++ 的 `vector<T>` 必须单一类型。

**C/C++ 对照**：`vector<string>` 里塞不进 `int`；Python 列表像"任意指针数组"。

### 5.1 切片 `[start:stop:step]`：负号的主战场

单元素 `[-1]`、`[-2]` 只是开胃菜，**切片**才是负号真正发光的地方。

```python
s = ["a", "b", "c", "d", "e"]
s[1:4]      # ["b", "c", "d"]             左闭右开
s[:3]       # ["a", "b", "c"]             从头
s[2:]       # ["c", "d", "e"]             到尾
s[-2:]      # ["d", "e"]                  后两个
s[:-1]      # ["a", "b", "c", "d"]        除最后一个
s[::2]      # ["a", "c", "e"]             隔一个取一个
s[::-1]     # ["e", "d", "c", "b", "a"]   反转（负步长经典）
```

**语法**：`seq[start:stop:step]`，三个参数都可省略；`step` 缺省 1。

- `step` 为**正**：`start` / `stop` 缺省时默认从**头**到**尾**。
- `step` 为**负**：`start` / `stop` 缺省时默认从**尾**到**头**（遍历方向反过来），所以 `s[::-1]` 能反转整个序列。

**C/C++ 对照**：C++ 没原生切片语法，要切 vector 得写 `vector<T>(v.begin()+i, v.begin()+j)`，还得自己保证 `i<=j`；Python `v[i:j]` 一行搞定，且**左闭右开**（与你熟悉的 `[first, last)` 习惯一致）。

**坑 1：下标越界会报错，切片越界不会**

```python
[1, 2, 3][100]      # IndexError: list index out of range
[1, 2, 3][1:100]    # [2, 3]   ← 不报错，超出部分静默截断
```

"不报错但结果不对"——这种 bug 调试时最隐蔽。

**坑 2：`s[:]` 是浅拷贝，不是同一对象**

```python
s2 = s[:]   # 新列表，改 s2 不影响 s
s2 = s      # 同一个对象，改 s2 等于改 s
```

**坑 3：反转的几种写法，省得用错**

```python
new = s[::-1]                  # 新列表，不动原列表
s.reverse()                    # 原地反转，无返回值（None）
for x in reversed(s): ...      # 迭代器，省内存
```

**坑**：混装虽灵活，但遍历时若假设"全是同一种类型"，就可能运行时 `AttributeError`——类型安全交给了你自己。

## 6. 函数机制：无重载 + 关键字实参

### 6.1 Python 不支持函数重载

```python
def f(x): ...
def f(x, y): ...    # 后者直接覆盖前者，不是"重载"
```

**为什么**：函数名只是个变量，指向函数对象；同名 `def` 后者覆盖前者（如同 `a=1; a=2`）。运行时没有"按参数签名分派"这一步（对比 C++ 编译期静态分派多个同名版本）。

**替代 / 满足类似需求的办法**：

| 需求 | 写法 |
|---|---|
| 参数个数可变 | 默认参数 `def f(x, y=0)` |
| 任意个位置参数 | `*args` |
| 任意个关键字参数 | `**kwargs` |
| 按类型自适应 | **鸭子类型**：函数不关心类型、只关心能否用，一个实现天然适配多类型（如 `double(x) = x + x` 对数字/字符串/列表都可用），根本不需要重载 |
| 官方近似重载 | `functools.singledispatch`：按第一个参数类型分派 |

### 6.2 关键字实参（keyword argument）

```python
flower(t, petals=6, size=70, color="hotpink")   # 按名传值
# 对比位置实参：flower(t, 6, 70, "hotpink")
```

**规则**：关键字实参必须放在位置实参之后；同一参数不能同时用位置和关键字绑定。

**好处**：可读、顺序随意、可只传想传的带默认值参数。你 08 课里 `pen.write(..., align="center", font=(...))` 的 `align=`、`font=` 就是关键字实参。

**进阶（定义端）**：`def f(a, **kwargs)` 用 `**kwargs` 把多余关键字参数收进字典。

## 7. 回调函数 与 `global` 声明

### 7.1 回调函数（callback）

**是什么**：把**函数本身**（函数对象，传名字、**不加括号**）传给另一个函数/框架，等事件发生时再由对方调用。

```python
t.ondrag(draw)                  # 对：把 draw 交出去，事件触发时才调用
# t.ondrag(draw())             # 错：当场调用一次，把返回值 None 注册进去
```

**典型场景**：turtle 的 `ondrag` / `onkey`，以及 08 课 `screen.ontimer(game_loop, DELAY)` 的游戏主循环。

**关键规则**：传的是函数，不是函数的结果 ⇒ **绝对不能加 `()`**。

### 7.2 `global` 声明

**是什么**：在函数**内部给模块层的变量赋值**前，必须先 `global 变量名`，声明"我要改的是外面那个"。

```python
is_first_drag = True
def draw(x, y):
    global is_first_drag     # 声明：改的是模块层的变量
    is_first_drag = False
```

**为什么**：不声明的话，Python 会把它当成新建的**局部**变量——外面那个完全没动；若之后又在函数里**读**它，会抛 `UnboundLocalError`。

**坑**：**仅读取**外部变量不需要 `global`，只有"赋值/修改"才需要。漏写 `global` 是交互程序最常见的隐性 bug。

## 8. 闭包：让函数自带状态

**是什么**：一个函数 + 它捕获的**外层局部变量**，打包在一起，让函数能"随身带着自己的数据"。

```python
def make_color_setter(color):     # color 是外层局部变量
    def setter():                 # 内层函数
        t.pencolor(color)         # 用了外层的 color → 形成闭包
    return setter                 # 把内层函数整个返回
```

**为什么需要它**：`onkey` / `ondrag` 要求回调**无参**，但你想给回调塞数据（如颜色）。工厂函数 `make_color_setter` 每次调用产出一个"记住了某个颜色"的无参函数，循环里注册 5 个就得到 5 种换色回调。

**生命周期**：被捕获的变量随返回的函数一起多活（正常函数返回后局部变量会销毁），可通过 `func.__closure__[0].cell_contents` 查看。

**C/C++ 对照**：最接近 C++11 **lambda 按值捕获** `[color]() { t.pencolor(color); }`。

**最坑的点——late binding（延迟绑定）**：闭包捕获的是**变量本身（按引用）**，不是它当时的值。在循环里直接捕获循环变量会翻车：

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)
print([f() for f in funcs])    # [2, 2, 2]  ← 三个都是 2！i 停在循环末尾
```

修法：
```python
funcs.append(lambda i=i: i)          # ① 默认参数当场固定值
# 或 ② 用工厂函数（make_color_setter 模式，每次调用独立绑定）
```

**替代写法**（本质也都是闭包）：
```python
screen.onkey(lambda: t.pencolor(color), key)        # lambda 简写
from functools import partial
screen.onkey(partial(t.pencolor, color), key)       # partial 预填参数
```

**和回调的关系**：闭包几乎总是和回调配套出现——"回调不能传参"就用"闭包给它带参"，两者是一套组合拳。
