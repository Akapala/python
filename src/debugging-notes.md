# 调试笔记：执行顺序与断点行为

> 记录一次调试探讨中理清的关键细节：Python 到底怎么执行、断点什么时候才会停、多实例如何区分。
> 结论比语法更重要——**"定义"和"调用"是两回事**。

---

## 1. Python 是逐行执行的，但"定义"不等于"执行函数体"

文件从上到下跑一遍，但不同类型的行做的事完全不同：

| 语句类型 | 执行时机 | 真正做的事 |
|---|---|---|
| `import xxx` | 顶层，加载时 | 导入模块 |
| `class Clock:` | 顶层，加载时 | 创建**类对象**（方法只是登记进去，方法体不跑） |
| `def main():` | 顶层，加载时 | 创建**函数对象**，绑定名字（函数体不跑） |
| 函数体内的语句 | 函数**被调用**时 | 才真正执行 |
| `if __name__ == '__main__':` | 顶层，加载时 | 判断，成立则调用 `main()` |

**关键区分：**

- `def` / `class` 这一行本身**会被执行**（创建函数/类对象）；
- 但它们**内部的代码体不会执行**，要等到被调用。

所以"程序从 main 开始"只是一种**表象**：前面的顶层语句其实都跑了，只是没有肉眼可见的动作；真正有输出、会循环的代码在 `main()` 里，而它是被文件末尾的守卫语句调用的。

---

## 2. `if __name__ == '__main__'` 是干什么的

```python
if __name__ == '__main__':
    main()
```

| 使用方式 | `__name__` 的值 | 结果 |
|---|---|---|
| 直接运行本文件 | `'__main__'` | 条件成立 → 调用 `main()` |
| 被别的文件 `import` | 模块名（如 `'hello_world'`） | 条件不成立 → **不**调用 `main()` |

好处：同一个文件既能当脚本跑，也能当模块被复用，不会一导入就自动执行。

---

## 3. 断点规则：执行流走到那一行才停

> **断点属于"代码行"，不属于某个对象/实例。程序执行到这一行，就停。**

函数体里的断点，必须等**函数被调用**、控制流进入函数体才会命中：

| 断点位置 | 什么时候停 | 相对 `main` |
|---|---|---|
| 顶层 `import` / `class` / `def` 那一行 | 文件加载时 | **main 之前** |
| `main` 函数体内 | `main()` 被调用时 | main 开始时 |
| `__init__` 函数体内 | 创建实例 `Clock(...)` 时 | main 开始后 |
| `run` / `show` 等函数体内 | 该函数被调用时 | main 开始后 |
| **从不被调用的函数**内部 | **永远不停** | —— |

一句话：**判断标准永远是"这一行有没有被执行到"。**

---

## 4. 实例化与断点：多实例会多次命中

`__init__` 是**每创建一个实例就调用一次**的方法，所以断点打在 `__init__` 里，会被命中多次：

```python
def main():
    c1 = Clock(23, 59, 58)   # 第 1 次进 __init__ → 断点停（self 指向 c1）
    c2 = Clock(1, 2, 3)      # 第 2 次进 __init__ → 断点再停（self 指向 c2）
```

调试流程：

1. **F5** → 停在 `c1` 的 `__init__`，`Locals` 显示 `hour=23, minute=59, second=58`，`self` = c1
2. **F5**（继续）→ 停在 `c2` 的 `__init__`，`Locals` 显示 `hour=1, minute=2, second=3`，`self` = c2
3. 再继续 → 没有第三次，程序往下走

> 注意：如果在 `while` 循环里反复调用的是 `obj.run()`，那**不会**再进 `__init__`；只有 `Clock(...)` 才会。
> `run()` 里的 `self._second += 1` 是**修改已有实例的属性**，和"创建对象"是两码事。

---

## 5. 断点处如何区分是哪个实例

在 `__init__` 断点里看这几点就能分辨：

- **`self`**：不同实例的对象地址不同（`<__main__.Clock object at 0x...>`）
- Watch 里加 **`id(self)`**：值不同 → 不同对象
- Watch 里加 **`self._hour`**：分别对应各实例的实参值

> `Locals` 顶层的 `hour` / `minute` / `second` 是**构造函数的形参（局部变量）**；
> `_hour` / `_minute` / `_second` 是**实例属性**，挂在 `self` 上，需要展开 `self` 或手动加 Watch 才看得到。

## 6. 调试配置：用 `debugpy`，不要用 `python`

`.vscode/launch.json` 里旧写法 `"type": "python"` 已被弃用（会弹警告），应改为新调试适配器：

```jsonc
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Python: 当前文件",
            "type": "debugpy",          // ← 旧值 "python" 已弃用
            "request": "launch",
            "program": "${file}",        // 调试当前打开的文件
            "console": "integratedTerminal"
        }
    ]
}
```

- 根因：Python 扩展把调试器拆成了独立的 `debugpy` 适配器。
- 若升级扩展后再出现类似弃用提示，优先查扩展迁移说明，不要忽略警告。

## 7. 调试流程 SOP（个人速查）

1. 在**会执行到**的行打断点（别打在从不调用的函数里）。
2. 确认调试配置 `type` 为 `debugpy`。
3. **F5** 启动；第一次停在哪，就说明执行流先到了哪。
4. 用 **F10（单步跳过）** / **F11（单步进入）** 观察：
   - `def`/`class` 只是"登记"，不会跳进函数体；
   - 调用语句（如 `main()`、`Clock(...)`、`clock.run()`）才会把控制流带进函数体。
5. `Locals` 看局部变量与 `self`；实例属性靠展开 `self` 或 Watch。
6. 断点在 `__init__` 时，**有几个实例就会停几次**。

## 8. 常见误区小结

| 误区 | 正解 |
|---|---|
| "所有代码都要等 main 开始才执行" | 顶层语句（import/class/def）在加载时就执行了；只有函数体等调用 |
| "断点在函数里，文件一加载就停" | 函数体断点要等函数被调用才停 |
| "类定义要创建实例才完成" | 类定义在 `class` 行就完成了；创建实例时执行的是 `__init__` |
| "断点属于某个实例" | 断点属于代码行；每个实例都会各自命中一次 |
| "`__init__` 只跑一次" | 每创建一个实例就跑一次 |
